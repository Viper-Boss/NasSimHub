# 安全边界与迁移要求

## 部署权限

API 的 8080、Cloudflare origin 的 7575/7576 仅供 Compose 私有网络使用，
不得另行发布到 LAN 或公网。默认仅发布本地 HTTPS 7577。
API 接受来自回环/私有网络的代理 IP 元数据；这要求 Compose 网络上的服务完全可信。
来源无法解析或来自公网时不接受转发 IP 头。origin 对公网直连请求不采信
CF-Connecting-IP 和 X-Forwarded-Proto。直接 HTTPS 入口始终覆盖客户端提供的元数据。
若需要把 API 或 origin 暴露给其他网络，必须先配置独立代理信任名单，不能沿用此边界。

fnOS 的 api/web 取消 privileged，但 trim 内核的数据目录访问限制仍需要 root
和 compose.fnos.yml 列出的少量能力；这不等同于非 root。硬件服务需要的权限另算。
不要把硬件服务的特权复制给 api/web。

OTA updater 持有 Docker socket 和部署目录写权限，属于宿主机可信计算基（TCB）。
Docker socket proxy 的写 API 依旧可能创建特权容器，单纯加一层代理不能消除宿主权限。
保留 token 门禁、离线签名、digest 锁定、私有监听；升级前备份与回滚。
现有 HOMESIM_* 转发凭据由 API 的转发器使用；不要把 credentials.env 注入网页或其他容器。
后续改为 secret 文件需要兼容现有按环境变量名引用的转发配置，不能直接删掉 env_file。

宿主 agent 的 Unix socket 以文件权限作为授权边界：socket 所属组的成员等同于
拥有 SIM 控制权限。只给 API 和管理员进程访问，不将第三方服务加入该组。
共享 token 方案需要同时升级 agent/API；不能只在一侧强制启用造成电话离线。

## 克隆安装的本地确认

GET /api/v1/provision 只在检测到克隆时生成数据目录内的
`.reset-confirmation-token`（0600），不会在 HTTP 响应或日志中返回其内容。
NAS 管理员在本地数据目录读取后，在重置页面同时输入机器标识与确认码。
POST 同时校验二者；缺失、错误或不可读的确认码均拒绝。
接受后仅写待重置标记，下次启动才执行清空。健康安装仍拒绝重置。
确认码仅用于这项操作，不得放入交接文档、截图、工单或仓库。
确认码文件损坏时由管理员在核对目标并备份后从本地移除损坏文件，再刷新页面生成新码。

## 发行与许可密钥拆分方案（尚未启用）

当前 release 与 license 使用相同的 Ed25519 公钥；签名域区分防跨协议重放，
但不能限制私钥泄露的影响。不要直接替换现有公钥，否则已部署更新和许可证会失效。

迁移顺序：由所有者离线生成独立发行密钥 → 在过渡版加入新公钥及 key_id
验证能力 → 用旧发行签名发布过渡版 → 确认设备升级覆盖 → 新版本只由新发行密钥签名 →
到约定截止版本去掉旧发行密钥。许可验证继续使用原许可公钥。
必须有旧设备升级、错误 key_id 拒绝、回滚与密钥失陷恢复测试，才可称完成。
本轮没有生成或替换私钥，也没有修改线上信任根。

当前 Go 1.26.5 构建的 ML-DSA 实现不可用，正式发布能力为 Ed25519；
不能将代码中存在的 go1.27 实现宣传为已启用的双签名。
启用 PQ 需要升级并验证发行工具、网关和设备端整条链，以及旧版本降级策略。

## iOS 配对与证书锁定方案（尚未启用）

iOS 长期配对凭据不同于浏览器 Cookie，现有可撤销机制应继续保留。
凭据到期/轮换需要增加客户端刷新协议、服务端 token 家族撤销和离线宽限，
并验证旧客户端重配对体验；不直接套用浏览器 30 天闲置策略。

SPKI pinning 需在首次可信配对时绑定具体网关，支持当前/下一把公钥双 pin、
明确的重新配对流程与证书轮换。不要钉死单张公网证书或默认信任首次未验证连接。
实施前需确定 Apple 签名团队与正式 bundle ID；现有 com.example.modemdeck
仅适用于开发，不能替所有者擅自选择并迁移签名身份。

## 研发工具与兼容命名

产品名为 NasSimHub，发行镜像为 viper-boss/nassimhub*。Go module、
MODEMDECK_* 环境变量、modemdeck Compose 服务名保留上游兼容身份，
升级时不要求用户迁移数据或变量；整体改名需单独双读迁移。

开发建议 Node.js 24（本轮验证 24.22.1），执行 npm ci 使用锁文件。
TypeScript 6 别名为 vue-tsc 提供编译 API；@typescript/native 是 TypeScript 7
sidecar，只运行 npm run typecheck:sidecar。二者不可直接互换包名。
当前依赖和构建已验证后不因“版本较新”而随意降级。
Vite 默认只监听 127.0.0.1；需要 LAN 预览时明确设置 VITE_DEV_HOST。
开发服务不用于公网部署。
